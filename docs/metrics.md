# Metrics

All metrics are computed for each question and then averaged, so each question counts
equally. Everything is produced by one command, `python run_all_evals.py`.

## Answer quality: LLM judges

Implemented in [`evals/judges.py`](../evals/judges.py).

| Metric | Judge input | Scores 1 when | Refusals |
|---|---|---|---|
| **Answer correctness** (KPI) | question, reference answer, answer | the answer states the same legal substance as the reference. Paraphrasing, extra correct detail and a different citation format are all fine. Every element of a short reference must be present. | 1 if the question should be refused, else 0. Answering a should-refuse question scores 0. |
| Groundedness | retrieved excerpts, answer | every factual claim traces to an excerpt, and each citation label points at the excerpt the claim came from | Always 1. This is why refusals are tracked separately. |
| Answer relevance | question, answer | the answer addresses what was asked. Answering and then naming a limit counts as relevant. | 1 if the question should be refused, else 0 |

- **Judge setup:** Claude Sonnet 5 at temperature 0, via OpenRouter. The answers are
  generated by Haiku 4.5, a different model.
- **Output:** the judge returns `{"reasoning", "score"}` as JSON. If the call fails or
  the JSON can't be parsed, the score is `None`, never a guessed 0.
- **Calibration:** human corrections are stored in
  [`evals/human_labels.json`](../evals/human_labels.json), each with a general
  *lesson*. The lessons are added to the matching judge's system prompt on every run.
  To import corrections from an edited spreadsheet, run
  `python run_all_evals.py --import-labels <file>.xlsx`.
- **Noise:** 1–4 questions (0.02–0.10) can flip between two runs of identical code.
  Treat a single-run change under about 0.05 as noise.

## Retrieval: computed by code, no judge

Implemented in [`eval_retrieval.py`](../eval_retrieval.py) and
[`eval_citation_ranking.py`](../eval_citation_ranking.py). Matching is done at the
level of whole articles, annexes and recitals, so "Article 13(2)" satisfies an
expected "article 13".

| Metric | Definition |
|---|---|
| Retrieval (strict) | 1 only if **all** expected sources are retrieved. If the question names a provision ("summarize Article 112"), every chunk of it must be retrieved. For should-refuse questions: 1 if the question was refused. |
| Recall@k | Share of expected sources found in the first k citations (k = 1, 3, 5, 8). |
| Precision@k | Share of the first k citations that are expected sources. **This is a lower bound:** the golden set lists only primary sources, so a useful supporting chunk counts as a miss. |
| Top-3 citation hit | 1 if at least one expected source is in the first 3 citations. |

## Guardrails (the release gate)

| Guardrail | Threshold |
|---|---|
| Should-refuse questions refused | all of them |
| Groundedness | no more than 1 question below the baseline run |
| Unsupported citations: an answer cites a provision that wasn't retrieved | ≤ 5% of answers |

## Cost and latency

| Metric | Source |
|---|---|
| Latency | Wall-clock time per question, recorded in the local results JSON. |
| Cost | OpenRouter's actual charge for each LLM call (`usage.cost`), attached to the LangSmith run and totalled for each question. Judge cost is not included in the reported cost per question. |
| LLM calls per question | Recorded by the agent (`llm_calls`). |
